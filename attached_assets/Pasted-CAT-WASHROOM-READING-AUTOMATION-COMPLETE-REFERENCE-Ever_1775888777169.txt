CAT WASHROOM READING AUTOMATION — COMPLETE REFERENCE
Every detail needed to replicate this automation from scratch. Last updated: April 9, 2026.

1. OVERVIEW
When the cat washroom light (light.cat_lights) turns ON, the app:

Checks server startup cooldown (30s) — ignores events during first 30s after boot
Determines light state from webhook body (state/action fields) or queries HA API (up to 3 retries with 1s delays, plus a verification query 500ms later if first says ON)
If light OFF → stops all playback, saves chunk progress, sends stop to tablet/TV, clears session
If light ON → checks cooldowns, then plays "One moment, checking your readings" via HA Cloud TTS on HA Voice speaker
Gets active semester settings from DB (storage.getActiveSemesterSettings)
Calculates current week number using getWeekNumber(today, semesterStartDate, readingWeekStart)
Finds next unlistened file by course priority (findNextFileByPriority)
If no cached files → syncs from OneDrive, then retries
Asks "Good morning/afternoon Bryn. Would you like to play [file description]?" via HA Cloud TTS
Waits up to 23 seconds for confirmation (webhook or input_boolean poll every 10s)
If no confirmation → stores late-confirm window (10 min), plays CHUM FM 104.5
If confirmed → plays "Okay, I will now play [file description]" via HA Cloud TTS on HA Voice speaker
Extracts PDF text, chunks it (~1400 chars each), generates Edge TTS audio per chunk
Plays chunks sequentially on Nest speaker, tracking progress in DB
On completion of all chunks → marks file as listened, auto-advances to next file

All are POST requests from HA automations to the app at http://172.24.1.204:5000:

POST /api/webhook/cat-lights — Main trigger. Body can include: { state: "on"/"off" }, { new_state: { state: "on" } }, { action: "turn_on"/"turn_off" }, or { to_state: "on"/"off" }. If body doesn't contain state, queries HA API directly (3 retries).

POST /api/webhook/cat-wash-stop — Toothbrush/knob stop trigger. Stops all cat washroom playback.
POST /api/webhook/cat-knob-press — Knob rotation. Body: { action: "volume_up" | "volume_down" | "stop" }
POST /api/webhook/voice-command — Voice commands. Body: { command: string }. Supported commands: "pause", "resume"/"rezoom"/"re-zoom", "stop", "skip", "back", "repeat", "status", "clear_player"

7. FULL LIGHT-ON FLOW (STEP BY STEP)
Webhook received: POST /api/webhook/cat-lights
Server startup cooldown: If server started less than 30s ago (SERVER_STARTUP_COOLDOWN_MS = 30000), return "ignored"
State resolution: Parse body for state/action/to_state. If none found, wait 1s then query HA API for light.cat_lights state (up to 3 attempts, 1s between). If first query says ON, verify with second query 500ms later (catches brief on/off flickers).
Light OFF handling: stopNestPlaybackWithGoodbye('light_off'), stop TTS session, stopAllCatWashroomSpeakers, send stop_playback to tablet+TV, clear playback session, set lastPlaybackStoppedAt
Light ON — Cooldown checks:
If catLightsPromptPending is true → skip (prompt already in progress)
If lastPlaybackStoppedAt was less than 60s ago → skip (post-stop cooldown)
If catWashManuallyStoppedAt was less than 120s ago → skip (manual-stop cooldown)
If playback already active and not stale → skip. Stale = chunk still at 0 after 3 min, or started more than 10 min ago
Verify light still ON: Query HA API — if light is actually OFF, abort
Set prompt pending: catLightsPromptPending = true, catLightsLastPromptAt = now
Return 200 immediately: { action: "processing" } — rest runs in background
HA restart window check: If 4:00-4:10 AM Toronto time, play "Home Assistant is currently restarting..." TTS, wait until 4:10, then re-check light
Early device wake (parallel): Wake tablet via ADB (KEYCODE_WAKEUP + brightness 255)
Immediate prompt (parallel):
Turn on HA Voice + Nest speakers (media_player/turn_on)
Set HA Voice volume to 0.50, Nest volume to 0.35
Turn off input_boolean.module_reading_confirmed, turn on input_boolean.module_reading_pending
Wait 1500ms
Play "One moment, checking your readings." via tts/speak on HA Voice (primary). Fallback: Edge TTS on Nest speaker
Wait 3500ms after ack plays
Get semester settings: storage.getActiveSemesterSettings() — if null, abort
Calculate week number: getWeekNumber(torontoDate(), semesterStartDate, readingWeekStart)
Find next file: findNextFileByPriority(allFiles, weekNumber)
If no cached files → syncOneDriveFilesForWeek, then retry
If cached file has priority > 1 → sync OneDrive first to check for higher-priority files
If cached file is priority 1 → use it, sync OneDrive in background
Wait for prompt + device wake to finish
Re-check light still ON — abort if off
No files found: Play CHUM FM 104.5 on cat washroom media group, clear prompt pending
File found — build TTS prompt: greeting (Good morning/afternoon based on hour) + "Would you like to play [file description]?"
Play prompt: tts/speak on HA Voice speaker (primary). Fallback: Edge TTS on Nest. If all fail: play CHUM FM
Wait 2s, then check light still ON
Wait for confirmation: Up to 23 seconds. Two methods:
Primary: catLightsConfirmResolve callback (set by /api/webhook/cat-lights-confirm)
Backup: Poll input_boolean.module_reading_confirmed every 10s
Reset booleans: Turn off both module_reading_pending and module_reading_confirmed
Not confirmed: Store late-confirm file + week + 10-min expiry. Play CHUM FM radio.
Confirmed: Check light still ON one more time. If off, abort.
Start playback: confirmTTS = "Okay, I will now play [file description]." → startConfirmedPlaybackFlow()

9. TTS MESSAGE DELIVERY (CRITICAL FIX — Apr 9 2026)
Problem: Confirmation and pause messages were using Edge TTS audio generation → upload to HA → play_media on Nest speaker. This pipeline was unreliable — messages cut off mid-word and sometimes didn't play at all.

Fix (commit f7c88c20c): Changed both confirmation and pause TTS to use HA Cloud TTS (tts/speak) directly on the HA Voice speaker — the same method used for the initial prompt messages which work reliably.

All prompt messages ("One moment...", "Would you like to play..."): Already used tts/speak on HA Voice (unchanged)
10. CHUNK PLAYBACK (startNestChunkPlayback)
If no chunks (text extraction failed), skip file, try next unlistened file
Load pre-prepared audio cache from file.preparedAudioPaths
Load checked chunks set from file.checkedChunks — skip already-checked chunks
For each chunk (starting from resumeFromChunk):
Check abort/session match — if aborted, save progress and break
Skip if chunk is in checkedChunksSet
Every 3 chunks: play attention prompt "Bryn, are you paying attention?"
Get audio: pre-prepared cache → pre-generated first chunk → look-ahead → generate on-the-fly
Estimate duration: max(5000, (wordCount/175) * 60000 + 1000) ms

Start look-ahead generation for next chunk (parallel)
Wait estimated duration
Save lastChunkIndex to DB
After all chunks: mark file as listened, auto-advance to next unlistened file

13. VOICE COMMANDS (POST /api/webhook/voice-command)
"pause": Aborts chunk loop, stops Nest speaker, saves progress, sets voiceCommandPauseState with auto-stop timer (10 min default). Plays "Paused. Say re-zoom to continue, or I'll stop in N minutes." via tts/speak on HA Voice speaker. N = fetched from HA automation duration (automation.motion_cat_wr_no_motion).
"resume" / "rezoom" / "re-zoom": Restores from voiceCommandPauseState. Re-fetches file from DB, re-extracts text, re-chunks, resumes from saved chunkIndex. Plays "Resuming [file description]."
"stop": Full stop. Stops all speakers, clears pause state, turns off Fire Stick + TV. Plays "Stopped. Your reading position has been saved."
"skip": Marks current file as listened (sets listened=true in DB). Finds next file. If found: starts playback with "Skipped. Now playing [next file]." If not: plays CHUM FM.
"back": Goes back one chunk (max(0, currentChunk - 1)). Restarts chunk playback from there.
"repeat": Replays current chunk.
"status": Announces "Currently playing [file], chunk [N] of [total]."
"clear_player": Nuclear reset — clears all playback state, stops all speakers, clears pause state.

SERVER_STARTUP_COOLDOWN_MS: 30,000ms (30s) — ignores all light events during first 30s after boot
CAT_LIGHTS_PROMPT_COOLDOWN_MS: 180,000ms (3 min) — minimum time between prompts
Post-stop cooldown: 60,000ms (60s) — after playback stops, ignore light-on events for 1 min

Confirmation timeout: 23,000ms (23s) — max wait for user confirmation

Chunk duration estimate: max(5000, (wordCount/175)*60000 + 1000) ms per chunk
Attention interval: Every 3 chunks, play "Bryn, are you paying attention?"
Edge TTS timeout: 10,000ms per chunk generation attempt
No-motion auto-stop: Default 10 min (read from HA automation duration). Stops paused playback.

26. CRITICAL FIX — MISSING DATABASE COLUMNS (Apr 9 2026)
Problem: The automation broke because the semester_settings table on the Pi's database was missing the course1_display_name, course2_display_name, and course3_display_name columns. These columns were added to the Drizzle schema but never pushed to the Pi's database via migration.

Root cause: The code calls storage.getActiveSemesterSettings() which SELECTs all columns including display_name columns. When these columns don't exist in the database, the query fails silently or returns an error, causing the entire automation to abort at step 11 (getting semester settings).

Fix: Manually run these ALTER TABLE commands on the Pi's PostgreSQL database:

ALTER TABLE semester_settings ADD COLUMN IF NOT EXISTS course1_display_name text;

ALTER TABLE semester_settings ADD COLUMN IF NOT EXISTS course2_display_name text;

ALTER TABLE semester_settings ADD COLUMN IF NOT EXISTS course3_display_name text;

Prevention: After any schema change in shared/schema.ts, always verify the Pi database has the new columns. The Pi uses a separate PostgreSQL instance that doesn't auto-migrate.
